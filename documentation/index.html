Overview

This project is an IoT control system designed to manage and control smart devices. It consists of a client-side application for user interaction, a server-side component for backend logic and device communication, and a database for storing configuration and log data. The system supports managing users, devices, rooms, scenes, and logging events. Communication with devices likely involves MQTT.

Client

The client application is built using React and Vite. It provides a user-friendly interface to interact with the smart home system. Key features include:

  • User authentication and management.
  • Device listing, adding, updating, and removal.
  • Room creation and management.
  • Scene creation, management, and activation.
  • Viewing system logs.
  • Importing and exporting settings.

Server

The server-side component is built using Node.js and Express. It handles API requests, interacts with the database, and communicates with IoT devices. Key responsibilities include:

  • Handling user authentication and authorization.
  • Managing device connections and communication (likely via MQTT).
  • Processing API requests for devices, rooms, scenes, and logs.
  • Storing and retrieving data from the database.

Database

The project uses a database to store persistent data such as user information, device configurations, room layouts, scene definitions, and system logs. The database schema is defined using Drizzle ORM.

Detailed documentation for database and schema files:

  • Shared Schema (shared/schema.ts)
    • The project uses a database to persist application data. Based on the file structure, it appears to use LokiJS for client-side data (possibly for mock data or local storage) and Drizzle ORM with a backend database (like SQLite, PostgreSQL, etc., as suggested by `drizzle.config.ts`) on the server. The database stores information about:

    • Users
    • Devices (with properties like ID, route, status, room association)
    • Routes (for device communication)
    • Logs (system events and actions)
    • Settings (application configuration)
    • Rooms (for organizing devices)
    • Scenes (predefined actions for multiple devices)

    The database schema is defined in shared/schema.ts.

API

The client and server interact through a RESTful API. The API endpoints allow the client to:

  • Authenticate users.
  • Manage users, devices, rooms, and scenes.
  • Retrieve system logs and settings.
  • Control devices (potentially via specific API calls that trigger MQTT messages).

The API provides the interface for the client to manage the smart home system.
